# 0001 - macOS開発環境管理にNix Flakesを採用する

## ステータス

承認済み

## コンテキスト

ChieさんのMacBook Pro（Apple Silicon）に開発環境（Python、R、ローカルLLM）を構築する。
Macの一般的な選択肢はHomebrewだが、再現性のある環境管理と、同僚への展開を考慮する必要がある。
ChieさんはGUIアプリ中心のユーザーで、開発ツールのみNixで管理することが求められる。

## 決定

Homebrewは使用せず、Nix（Flakes有効化）＋nix-darwin＋home-managerで開発ツールを管理する。

## 根拠

- **再現性**：`flake.lock`により依存関係が完全にロックされ、同僚が同じ設定を再現できる
- **Pixi との親和性**：Pixiもロックファイルで再現性を保つツールであり、思想が一致する
- **Homebrew不使用の理由**：HomebrewとNixは同じ層を取り合い、PATHの競合や管理の混乱が起きやすい。単一のパッケージ管理ツールに統一することで摩擦を減らす
- **macOS標準との共存**：GUIアプリはApp Store・公式サイトから引き続きインストールし、開発ツールのみNixで管理することで、非エンジニアのユーザー体験を損なわない

## 却下した選択肢

- **Homebrew**：広く使われているが再現性が低く、NixとのPATH競合リスクがある
- **Homebrew + Nix の併用**：複雑になり管理コストが増す
- **手動インストール**：再現性なし

## 結果

- ブートストラップ手順が「Nixをインストール → `nix-shell -p git` → clone → apply」とシンプルになる
- READMEに記載する手順が明確になり、非エンジニアの同僚も再現できる
