# 0003 - NixとPixiの役割分担（ツールチェーン vs プロジェクト依存関係）

## ステータス

承認済み

## コンテキスト

NixもPixiも再現性のある環境管理ができるため、責務が重複する。
Chieさんの用途はPython・Rを使ったデータ分析であり、プロジェクトごとに異なるパッケージセットが必要になる。

## 決定

- **Nix（home-manager）で管理**：git、Pixi自体、Ollama、Open WebUI、VS Code など「常駐する開発ツール」
- **Pixiで管理**：プロジェクトごとのPython・Rパッケージ（pandas、matplotlib、jupyterlab など）

## 根拠

- **責務の明確化**：Nixは「マシンに常にある道具」、Pixiは「プロジェクトで使う材料」と説明できる
- **Pixiのcondaエコシステム活用**：科学計算系のPython・Rパッケージはcondaチャンネルの方が依存関係の解決がスムーズなケースが多い
- **非エンジニアへの説明のしやすさ**：「プロジェクトフォルダで`pixi install`すれば動く」と一言で説明できる
- **Nixのオーバーヘッド回避**：プロジェクトごとの依存関係をNixで管理するとdevShellの記述が複雑になる

## 却下した選択肢

- **Nixですべて管理**：プロジェクトごとのdevShell記述が複雑で、非エンジニアには難しい
- **Pixiだけで管理**：OllamaなどのシステムツールをPixiで管理するのは適切でない

## 結果

- このリポジトリはツールチェーン（Nix管理）のみを扱う
- Pixiの`pixi.toml`は各プロジェクトのリポジトリで管理する
